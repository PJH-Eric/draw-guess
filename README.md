# 你畫我猜（draw-guess）

可愛風的畫圖猜謎小遊戲。輪流當畫家：畫家從三個題目挑一個畫出來，其他人把答案打進猜題框。
畫布是**小畫家風格**的（鉛筆、筆刷、直線、矩形、橢圓、橡皮擦、油漆桶、顏色、筆寬、復原／重做／全部清除）。

支援單機自己練習作畫與經典模式跨裝置對戰（大廳、房間、觀戰、邀請連結），以及兩個線上模式：「接力模式」大家投票選題、輪流接力作畫給一人猜；
「畫圖傳話（Beta）」一張畫接一張照著畫下去，最後一人猜答案再揭曉整串。
手機、平板、桌機，直向橫向都可以玩。

---

## 快速開始

```bash
npm install
npm start
# 瀏覽器開 http://localhost:3030
```

Windows 可以直接雙擊 **`啟動遊戲.bat`**（會自動安裝相依套件、啟動伺服器並開啟瀏覽器）。

啟動後畫面會印出這台電腦的「同網段」網址，例如 `http://192.168.1.20:3030`。
同一個 Wi-Fi 的另一台手機或平板直接開那個網址，就能一起玩。

> 只想玩單機的話，其實連伺服器都不用開：把 `public/` 用任何靜態網頁伺服器送出去就可以。

## 怎麼玩

### 一局的節奏

| 階段 | 發生什麼事 | 時間 |
| --- | --- | --- |
| 選題 | 畫家從 3 個題目裡挑一個；沒選的話系統幫他挑第一個 | 15 秒 |
| 作畫 | 畫家作畫，其他人猜；全部猜中或時間到就結束 | 線上預設 90 秒（60–120 可調）；單機練習不限時 |
| 公布 | 公布答案與這一題的得分 | 7 秒 |

線上房間每個人輪流當畫家，每人畫 `rounds` 次（預設 2 次，最多 5 次）。全部畫完之後分數最高的人獲勝。
單機練習不計分也沒有這個「畫完就結束」的概念，不限次數，練夠了自己離開就好，不需要另外設定。

### 分數

- **猜對的人**：`100` + 時間獎勵（最多 `200`，剩越多時間越高）+ 名次獎勵（`60 / 40 / 25 / 15 / 10`）
- **畫家**：每有一個人猜中 `+40`；全部人都猜中再 `+60`。沒有人猜中就 `0` 分。
- **很接近了**：沒猜對，但猜中題目一半以上的字（無條件進位：1～2 字中 1 個、3～4 字中 2 個、5～6 字中 3 個），只私下提示猜的人、不加分。門檻一律看題目本身的字數，同義詞比較短也不會放寬。

### 題目提示（畫家手上的三張牌）

提示不會隨時間自動出現，一律由**畫家主動按**，而且只能依序給、給了收不回來：

| 順序 | 提示 | 猜題者看到什麼 |
| --- | --- | --- |
| ① | 字數 | 題目有幾個字就出現幾條底線，例如「漢堡」→ `＿＿` |
| ② | 種類 | 公開題目的分類，例如「食物」 |
| ③ | 一個字 | 在底線上隨機填回其中一個字，例如 `漢＿` 或 `＿堡`，每個字都可能被翻開。單字題沒有這一張（翻了就是答案） |

畫家還沒按提示前，猜題者連題目有幾個字都不知道。
提示區塊是畫家專屬的小面板，橫式擺在**畫布正上方、玩家名稱旁邊**，跟畫圖工具列分開；
一行放不下就自己掉到下一行（橫向時排到名稱左邊，避開右上角的固定按鈕）。
它刻意做小（高度 34～40px，低於一般按鈕的 46px 下限），把空間讓給畫布。

### 畫家參考範本

選題後，畫家可按題目旁的「查看範本」，切換「起筆／加細節／完整圖」三個階段，再按「回去畫畫」繼續作畫。支援繁中與英文介面、手機和平板直橫向及桌機；線上回合查看範本時仍繼續計時。

題庫 **5,500 題全部都有離線範本**（卡通動漫類的作品與角色有版權，範本只放「憑記憶畫」的提示圖，不畫角色造型），一律是「遊戲 12 色＋平塗＋深色輪廓」的簡單插畫，玩家用遊戲內的畫筆、形狀與油漆桶就能照著畫出來。配方放在 `public/js/refs/rNNNN.js`（每 40 題一檔，201 檔，依題目在題庫的原始順序分檔，不出題的題目也佔位；第 2000 題之後的區塊用 `K.Q`／`K.N` 簡寫，寫法見《範本繪製手冊》第 7 節），選到題目時才惰性載入；引擎見 `reference.js`、`reference-path.js`（SVG 路徑解析）與 `reference-kit.js`（積木庫）。範本分成起筆、加細節與完整圖三階段，不載入外部圖片，也不會加入、覆蓋或儲存到玩家作品裡。重畫或新增範本的規範見 `範本繪製手冊.md`，`node scripts/reference-lint.js all` 可檢查全部配方，`node scripts/reference-sheet.js --range 0-39 --out x.png` 可輸出預覽圖。

線上投影的 `referenceId` 只在作畫階段提供給當回合畫家；猜題者與觀戰者拿不到識別碼，也沒有範本入口。題目或回合改變時自動關閉舊範本。

執行 `node tests/reference.js` 與 `node tests/reference-coverage.js` 可檢查全部題目的筆畫範本、三階段輸出與成語組圖。`npm run test:browser` 會在八種視窗尺寸檢查雙語範本、焦點、作品保留與角色權限，截圖位於忽略版控的 `screenshots/`。

### 畫布工具（參考小畫家）

| 工具 | 快捷鍵 | 用法 |
| --- | --- | --- |
| 鉛筆 | `P` | 按住拖曳畫線 |
| 筆刷 | `B` | 同鉛筆，線粗一級 |
| 直線 | `L` | 從起點拖到終點，放開才定形 |
| 矩形 | `R` | 拖出對角線；可勾「填滿」 |
| 橢圓 | `O` | 拖出外框；可勾「填滿」 |
| 橡皮擦 | `E` | 擦掉畫錯的地方 |
| 油漆桶 | `F` | 點一下填滿封閉區域 |
| 復原 / 重做 | `Ctrl+Z` / `Ctrl+Y` | — |

**刻意沒有做的：作畫時的文字工具、對局中的聊天室。** 畫家如果在猜題進行中能打字，
就可以直接把答案寫出來或說出來，那就不叫你畫我猜了。對局中唯一能打字的地方是猜題框，
而且只有猜題者看得到它。左側操作摘要裡的「猜題紀錄」是唯讀的，顯示誰猜了什麼、誰猜對了。
等待畫面另外有個**聊天室**可以先聊幾句——那時候還沒有題目、也沒有答案，不會有外流的風險，
開始對局後就會跟著收起來，詳見下面「經典模式」。

## 單機練習

單機練習**沒有電腦對手，也不計分**，就你自己一個人，單純練習下筆用的。

跟線上房間一樣走同一套 `Rules` 規則引擎，只是玩家名單裡永遠只有你一個人：
挑一個題目、盡情畫，畫完（或不想畫了）按**「換題」**就換下一題並公布答案。
因為沒有電腦對手要等，**真的不限時、不限次**：選題不會倒數自動挑、作畫不會時間到、畫再多題也不會跳結算，
練夠了直接離開就結束（線上房間為了不讓其他真人乾等太久，上限小得多：5 次、120 秒，而且可以調）。
公布答案時可以按「下一題」馬上換題，不用等倒數。
（以前是拿引擎上限 999 次、99999 秒假裝不限，結果選題還是 15 秒倒數、畫滿 999 題還會跳一張「你 0 分」的結算。
現在 `Rules.createState({ unlimited: true })` 直接關掉所有期限跟結束條件。）
單機練習也不套用線上對局的累積筆畫與點數上限，持續作畫不會因為手繪分段累積而停止接受新筆畫。

畫布下方提供 **存檔**、**下載圖片**、**載入**：存檔下載 `.drawguess.json` 作品檔，保留題目和可編輯筆畫；下載圖片匯出含底色的 1400×1400 PNG。
載入作品檔後可以繼續作畫、復原或清除，也可以從單機設定頁的「載入作品」直接恢復作品。
若目前畫布已有筆畫，載入前會提示覆蓋確認。PNG 是圖片匯出格式，繼續編輯請選擇作品存檔。

因為只有你自己，「猜題」「提示」「分數」「操作摘要」這些跟別人比賽的東西在單機裡都用不到：
猜題框、左側操作摘要、畫布上方的玩家分數列與三張提示、上排的階段與倒數全部拿掉，
「畫完了」這顆通知用的按鈕也藏起來，以「換題」切換題目。空出來的空間全部給畫布：
直向時上排只剩「返回＋題目」一列；橫向時連這一列都搬進右側工具欄最上面，畫布從最上面一路畫到最下面。

單機手機工具至少 44px，平板工具為 48px；「放大工具列」仍可進一步放大。手機色盤可左右滑動，復原、重做、清除與筆寬放在同一列。
作品操作列依序為「存檔／下載圖片／載入／換題」：直向排成四欄，橫向排成兩欄。矮螢幕橫向只捲動工具區，作品操作始終保留在底部。

| 尺寸 | 視窗 | 單機畫布（改版前 → 改版後） |
| --- | --- | --- |
| 手機窄版直向 | 360×640 | 312 → 350 |
| 手機直向 | 390×844 | 370 → 380 |
| 手機橫向 | 844×390 | 272 → 384 |
| 小手機橫向 | 667×375 | 257 → 369 |
| 平板直向 | 768×1024 | 686 → 750 |
| 平板橫向 | 1024×768 | 606 → 760 |
| 桌機寬版 | 1440×900 | 738 → 894 |

## 經典模式

- **大廳**：開房、用房號加入、房間列表（房名、人數頭像、等待中／進行中與進度、觀戰人數、房主、規則 chip）、觀戰按鈕。列表可依題目語系、題目種類篩選，也能只看還有空位的房間；「快速加入」會進入第一間等待中、有空位、符合篩選的房間。滿房的房間「加入」會變成停用的「已滿」。
- **房間**：2–8 人**真人**（線上沒有電腦對手）；建立房間前會先在「開房間設定」選好房名、每人輪數、每題秒數與題目難度。進入等待中的房間後，房主仍可在中央「房間設定」調整規則——規則那三項改成下拉選單、標籤跟選單同一行（自己刻的按鈕＋清單，不是瀏覽器原生的 `<select>`，樣式跟卡片其他按鈕一致），房號跟玩家名單也一起縮小，這張卡才擠得出空間放下面的聊天室。寬螢幕（≥900px，例如平板橫向、桌機）這張卡改成**兩欄**：左邊房號、名單、規則，右邊邀請、聊天室，一個畫面看完不用捲；手機跟平板直向維持一欄。邀請區的網址欄跟「產生連結／複製／撤銷」排在同一行。**房主不用按「準備好了」**，只有一顆「開始！」——其他玩家都準備好就能開始；「改成觀戰」「離開房間」是小一號的次要鈕。卡片頂端會讓出右上角固定鈕的高度（手機上不會再蓋到標題），卡片開著時提示訊息改從上方出現，不會蓋住底部按鈕。玩家名單改成一列一個玩家、寬度滿版、文字置左（以前是置中的小 chip），不再另外顯示「x / y 位玩家」的字（列表本身數得出人數）；這幾項在手機直向跟平板都同步縮小過，不會有一邊擠一邊鬆的情況。
- **等待畫面的聊天室**：房間設定卡裡「邀請朋友」下面有個聊天室，只在還沒開始（`phase === 'waiting'`）跟結算畫面才會出現；一開始對局就整塊收起來，伺服器端 `room:chat` 也會直接擋掉，不是只有畫面上藏起來而已。別人聊天或按準備時，卡片是「就地更新」，打到一半的字、注音選字跟 iPhone 鍵盤都不會被打斷。
- **暱稱**：沒取名字的人不會全都叫「玩家」——第一次要用到名字時會自動配一個「形容詞＋小動物」的可愛暱稱（例如「勇敢小貓」），把欄位清空也會再配一個；同一間房裡撞名會自動接編號（小明、小明2），猜題紀錄才分得出誰是誰。
- **離開房間**：等待畫面的「房間設定」最下面有「離開房間」（房主是「退出房間」）；房主退出會把房主交給下一位**玩家**（沒有玩家才輪到觀戰者），最後一個真人退出房間就關閉。房主按「改成觀戰」時，房主也會交給下一位玩家；房間裡只剩自己一個玩家時不會出現「改成觀戰」（改下去房間就關了）。
- **公布答案時按表情**：每一題公布答案時，卡片上有這一題作品的小縮圖與 ❤️ 喜歡／😂 好好笑／👏 畫得好三顆表情鈕。這一局的玩家（畫家本人除外）每種表情一題可以按一次，再按一次收回；觀戰者只看得到數字。空白畫布的題目沒有表情列。
- **最佳畫家**：結算時收到表情總數最多的畫家拿到「🎨 最佳畫家」（平手並列，一個表情都沒有就從缺）。只是稱號、不加分，會跟名次一起出現在分享的結算圖片裡。
- **本局畫廊**：結算畫面列出這一局每一張有畫東西的作品（題目、畫家、收到的表情），點縮圖看大圖，可以上一張／下一張（也能用 ← →）並「下載圖片」（1400×1400 PNG）。筆畫只在結算後用 `room:gallery` 另外要一次，不會跟每次同步一起送；對局中拿不到，避免還沒公布的題目外流。中途加入的人也看得到整局的畫廊。單機練習不限次數，沒有畫廊。「再來一局」或「回房間」後畫廊就清掉。
- **一局結束後**：結算畫面上房主有兩個選擇——「再來一局」直接用同一批人、同樣規則開下一局（玩家席至少要 2 人）；「回房間」則帶大家回到等待畫面，可以聊天、改規則、重新按準備，再由房主開始。非房主看到的是「等房主開始下一局，或帶大家回房間」。結算畫面也能聊天（答案都公布了）。更早以前是「全員投票再玩一局」，有一個人掛機就全部卡住，所以改成由房主決定。
- **投票請玩家離開**：右上角「對局設定」裡可以對另一位玩家發起投票（等待中、對局中都可以）。發起人自動算一票；除了被投票的人以外，玩家**過半數**同意就把他請出房間，30 秒內沒過半就作廢。至少要 3 位玩家才能發起，觀戰者不能發起也不能投票，同一個人發起後有 60 秒冷卻，同時只會有一場投票。被請出去的人 5 分鐘內進不了同一間房（當觀戰也不行）；對局中被請出去的是畫家時，這一題直接結束換下一位。
- **角色**：玩家（可畫可猜）與觀戰者（只能看）。位子滿了時，新來的人會被**明確**降為觀戰，不會默默佔位；
  對局進行中只要還有空位，中途加入或觀戰者按「下場一起玩」都能**直接當玩家**，自動排在目前順位的**最後一位**——
  這一輪還沒排到他就會排進去，不用等這一局結束。
- **邀請連結**：`?room=XXXX&invite=<token>`。token 32 個十六進位字元、有效期 60 分鐘、最多 20 人次，可撤銷。
  連結不綁身分——房主不用先幫對方選好「一定是玩家」或「一定是觀戰」，開啟後**會先停在大廳**顯示房號與可編輯的暱稱欄位，
  自己選要「加入當玩家」還是「加入觀戰」才送出加入請求；改暱稱不會改變自己選的身分。
- **斷線重連**：座位保留 60 秒，用同一個 `clientId` 回來就能回到原位。在房間或對局中**重新整理頁面會自動回到原本的房間**（房號只記在這個分頁，按「離開房間」就忘掉）；房間已經不在就停在大廳並說明原因。
- **存活偵測**：伺服器每 10 秒探測一次、10 秒沒回應就標成離線（最久 20 秒）。用戶端在回到前景（`visibilitychange`／`pageshow`）或網路恢復（`online`）時會主動探測：已掉線就跳過退避時間立刻重連，連線看似還在但 4 秒內沒回條就當成殭屍連線直接重連。
- **房主離線交接**：等待或結算畫面的房主斷線超過 20 秒，房主先交給最早加入、仍在線的玩家（座位照樣保留 60 秒）。
- **閒置回收**：等待／結算畫面超過 30 分鐘沒有任何動作的房間自動關閉。
  畫家斷線的話，題目列會顯示「畫家斷線了，最多等 15 秒」。逾時會跳過這一題並用掉這次作畫機會，座位照樣保留。
- **同一局裡離開又回來**：分數跟已經畫過的次數都會接回去，不會回來就歸零、又被多排一次畫。
- **身分憑證不外流**：用戶端存在本機的 `clientId` 是重新連線用的憑證，房間裡看到的是伺服器用 HMAC 算出來的公開 id，
  抄了別人的公開 id 也冒用不了他的座位（包括房主）。所有用戶端送來的欄位都只收真正的字串／數字，每個事件處理都有 try/catch，
  一個怪封包不會讓整台伺服器掛掉。

### 對局進行中中途加入

線上房間的對局中，人可以一直加入（只要位子沒滿），每個中途加入的人都會排在**目前順位的最後一位**；
如果一直有人加入，最後一位就會一直往後移，這一場的總題數也跟著重算，
不是開局時就訂死的一個數字（判定方式見下面）。

因為人數在結束前都可能再變，畫面上**一律只顯示目前第幾題**，不顯示「/ 總題數」的分母——
線上房間是因為人數變動導致總題數不是固定的；單機雖然沒有這個問題，但乾脆兩邊用同一套顯示方式，簡單清楚。

中途加入的人是**真正的玩家**，不是先當觀戰再手動下場：這一局結束、房主帶大家回房間之後，
他一樣坐在玩家席，不用額外操作；反過來，之前那種「先降觀戰、要自己點下場才能算數」的流程容易漏按。

結束的判定是**每個人都畫滿「每人畫幾次」**，不是「輪到第幾輪」：有人中途離開時，順位會往回退一格，
下一位不會被跳過，也不會有人連畫兩次或少畫一次；總題數 = 已經畫完的題數 + 每個人還欠的次數，一有人進出就重算。

### 房間什麼時候會關閉

房間生命週期只看**實體玩家**（坐在玩家席的真人）。觀戰者不算。

實體玩家歸零（最後一個真人離開、退出，或斷線超過 60 秒保留期）→ 伺服器**立刻**關閉房間：
邀請全部失效、對局計時器停掉、從大廳列表移除、廣播 `closed`，
觀戰者會看到「房間已結束」與回大廳的入口。關掉之後**不會**因為重新連線或舊邀請復活。

## 接力模式

只有線上。首頁的「接力模式」是獨立入口，進去的大廳只列接力房（一般大廳也看不到接力房）；
大廳聊天室兩邊共用，開房公告的房名前會加上 `🔁Relay β｜` 標記。

每題一人當**猜題者**，其餘玩家都是**畫家**：

1. **投票選題**：畫家從 4 個候選題投票（10 秒，可以改票）。全部投完提前開始；平手從同票題目隨機，沒人投就隨機。只顯示票數，不顯示誰投哪題。
2. **3、2、1、開始！**
3. **接力作畫**：接力順序每題重新隨機，同一題三圈沿用同一順序；畫面上的玩家列就是接力順序，標出「正在畫」「下一棒」。
   每一棒一定畫滿秒數、不能提早交棒；工具不設限制，可以擦掉或清空別人的畫，「復原」收回畫布上最後一筆。
4. **換棒緩衝 3 秒**：畫布鎖住，下一棒的人手機震動＋音效、畫面大字「換你畫！」。最後一棒之後也有 3 秒緩衝，之後才公布答案。每題最多三圈。
5. **公布答案 7 秒**：只顯示完成圖，可以對整張圖按愛心／大笑／拍手。

猜題者隨時可猜（含緩衝），次數不限；猜錯的內容大家都看得到，「很接近」只提示猜題者，畫家看得到猜題者「輸入中…」。
猜題者可以自己按提示（字數 → 種類 → 揭一個字），每用一張之後的得分打六折；也可以「放棄」，直接公布答案、這題沒人得分。

| 項目 | 規則 |
| --- | --- |
| 人數 | 3–8 人；遊戲中人數低於 3 人就直接結算 |
| 房主設定 | 每人當猜題者 1–5 次（預設 1）、每棒 7／12／17 秒（預設 12）、題型（預設混合）、種類、題目語系 |
| 猜題者順序 | 照座位順序輪流 |
| 計分 | 第一棒 300、最後一棒 100，中間平均遞減；猜題者與當下作畫者同分；緩衝中猜中算上一棒；接力中不顯示這棒值多少分 |
| 聊天與表情 | 畫家之間可以聊天（底部框）、沒在畫的畫家可以對當下作畫者丟「加油／笑死／崩潰」，猜題者兩者都看不到；觀戰者看得到答案 |
| 中途進房 | 這一題先觀戰，下一題加入接力順序，並補排他當猜題者的輪次 |
| 斷線 | 猜題者斷線，這題直接公布答案；輪到的畫家斷線就跳過換下一位（伺服器給 3 秒緩衝，重新整理頁面不會害整題結束） |
| 結算 | 照總分排名，頒「神猜手」（當猜題者拿最多分）、「接力王」（當畫家拿最多分）、「關鍵一筆」（最多題在他那一棒被猜中）；畫廊放每題完成圖並列出參與畫家 |

接力規則在獨立的 `public/js/relay-rules.js`，一般模式的 `rules.js` 程式路徑不受影響。
GA4 事件名稱不變，接力房帶 `mode=relay`；接力大廳與接力房送虛擬路徑 `/relay` 的 page_view。

## 畫圖傳話（Beta）

只有線上。首頁第三個模式按鈕「畫圖傳話（Beta）」是獨立入口，進去的大廳只列這種房（一般與接力大廳都看不到）；
大廳聊天室共用，開房公告的房名前會加上 `📞Telephone β｜` 標記。

3–5 人，每一輪傳一串：從這一輪開頭的人起照座位往下，每人輪一次，前面每格都是作畫，最後一格猜答案。

1. **挑題**：開頭的人從題庫 3 個候選挑 1 個（15 秒，時間到沒選就用種子亂數隨機挑）。
2. **換手 5 秒**：每次換人先倒數 5 秒，輪到的人看上一張畫（開頭的人看題目），倒數完才能動手。
3. **照畫**：開始作畫後上一張畫就收起來，憑記憶畫；工具與一般模式相同，畫好按「交出去」，時間到就把畫一半的照傳。
4. **觀看**：正在畫的時候，前面已經畫完的人與下一位可以即時看著畫（例：ABCD，A 畫只有 B 看得到；B 畫 A、C 看得到；C 畫 A、B、D 看得到）；再後面的人看不到；觀戰者（含下一輪才加入的人）全部都看得到，包括題目。
5. **猜答案**：最後一人看上一張畫寫答案（最長 40 字），可以用提示（字數 → 種類 → 揭一個字，每張 ×0.6），
   也可以偷看前面的畫（第一張 ×0.3，越後面越接近 ×0.7）。時間到就用打到一半的草稿送出，沒寫顯示「（沒寫）」。
   這時其他玩家可以左右翻看這一輪所有的畫（沒有題目），觀戰者也可以。
6. **中間的人也能猜**：不是開頭、也不是最後的人，交出畫之後可以一直猜原本的題目直到猜中，猜中 50 分、每猜錯一次少 10 分（最低 10），不能用提示；猜錯只有自己知道，猜中時大家看到「某某猜中了」（不顯示題目）。這個分數跟整串分開算，已經猜中的人不會被找去代猜。
7. **揭曉**：一次列出整串（題目 → 每個人的畫 → 答案），每格可以按愛心／大笑，可以聊天；接著下一輪換下一位開頭。

| 項目 | 規則 |
| --- | --- |
| 人數 | 3–5 人；第 6 人起只能觀戰；中途進房先觀戰，下一輪起加入；遊戲中剩不到 3 人立即結算 |
| 房主設定 | 每張畫 30／45／60 秒（預設 45）、猜答案 20／25／30 秒（預設 25）、輪次 1–3（預設 1）、題型、種類、題目語系 |
| 計分 | 猜對時整串的人依順序從 300 平均遞減到 100，再乘這一輪所有提示倍數（大家一起扣）；猜錯或沒寫全部 0 分；被跳過的人不得分 |
| 聊天 | 傳話進行中關閉（輸入框隱藏、伺服器也拒收）；等待室、揭曉與結算時可以聊 |
| 斷線 | 輪到的人斷線 5 秒沒回來就跳過，上一張畫直接交給下一位；最後一人斷線由前一位代猜 |
| 結算 | 照總分排名，頒「最好笑」（被按最多表情那一格的作者，沒人按就不頒）；畫廊放每一張畫 |

計分範例（4 人）：猜對 300／233／167／100；用了字數提示 180／140／100／60；偷看第一張 90／70／50／30。

規則在獨立的 `public/js/telephone-rules.js`，畫面在 `public/js/app/telephone.js`，一般模式與接力模式的程式路徑不受影響。
GA4 事件名稱不變，帶 `mode=telephone`；這個模式的大廳與房間送虛擬路徑 `/telephone` 的 page_view。

### 改完前端之後

```
npm run build     # = 語系拆檔 + 接樣式表 + 更新版本參數
```

- 樣式改 `public/css/parts/*.css`，不要改 `style.css`。
- 介面文字改 `public/js/locales.js`，不要改 `locales/ui.*.js`。

### 設計原則

1. **規則核心與畫面／網路分離。** `rules.js` 只有「狀態 + 行動 → 新狀態」，時間由呼叫端傳進來。
   單機、伺服器、測試跑的是同一份，不會漂移。
2. **伺服器說了算。** 用戶端送的是「意圖」，房間權限由 `lib/rooms.js` 判斷、遊戲規則由 `rules.js` 判斷。
3. **隱藏資訊只走投影。** 答案只在 `state.wordId`；要送出去的東西一律經過 `Rules.toPublic(state, viewerId)`，
   只有當回合畫家拿得到答案與選字清單。操作摘要在揭曉前也不會寫出答案。
4. **可重現的隨機。** 題目、揭字順序、畫家順序都用可注入的種子亂數。

## 版面與設定

### 畫布最大化

畫布是正方形（筆畫座標統一在 0..1000，所以同一張圖在任何裝置上長得一樣），
邊長 = 可用空間的**較短邊**。所以「把高度讓出來」比什麼都有效：

- **直向**：操作列在畫布下方（寬度夠用、高度珍貴）。窄螢幕時工具、顏色、
  粗細三條各自變成可以橫向撥動的帶子，避免換行成四五排把畫布壓扁；
  「畫完了／跳過這題」釘在右邊不會被撥走（橫向時是上下疊在工具欄底部）。
  畫面比較高的手機（高度 ≥740px）上下本來就有空白，就改成顏色排兩排全部顯示、粗細與復原鍵不用滑，
  「跳過這題」自己一排撐滿；平板直向工具鈕放大到 48px 並撐滿整個寬度。

**「畫完了」不會結束這一題**：它只是廣播一句「某某說畫完了，快猜！」，時間照跑、畫家還能補筆畫。
這顆鈕**不會鎖起來**——補了幾筆想再叫大家看一次很正常，所以同一題想按幾次就按幾次，每按一次就再廣播一次。
真的要提早收掉這一題、公布答案的是下面那顆**「跳過這題」**
（對局設定裡的「跳過這一題（我畫不出來）」是同一個動作）。
- **橫向／寬螢幕（≥560px 且橫向）**：操作列移到畫布**右側**。
  橫向時寬度本來就有剩、高度才是瓶頸，這樣畫布可以吃滿整個高度。
  工具列固定分四組：畫圖工具 → 顏色 → 粗細 → 復原／重做／清除（三顆一定在同一排）。
  猜題者、觀戰者沒有工具列，右側這欄會收掉、畫布置中。題號只顯示在題目列（上排不再重複一個「第 N 題」）。

實測畫布邊長（線上畫家視角，工具列展開；單機畫布更大，見上面「單機練習」）：

| 尺寸 | 視窗 | 畫布 | 佔視窗較短邊 |
| --- | --- | --- | --- |
| 手機窄版直向 | 360×640 | 312×312 | 87% |
| 手機直向 | 390×844 | 370×370 | 95% |
| 手機橫向 | 844×390 | 272×272 | 70% |
| 小手機橫向 | 667×375 | 257×257 | 69% |
| 平板直向 | 768×1024 | 686×686 | 89% |
| 平板橫向 | 1024×768 | 606×606 | 79% |
| 桌機寬版 | 1440×900 | 738×738 | 82% |

### 工具按鈕的大小

畫布工具（工具、顏色、筆寬、填滿）**刻意做得比一般按鈕小**：它們數量多、
又要一直佔著畫面，做成 48px 會把畫布擠掉一大塊。實際尺寸是 44/40px，
窄版與矮橫向再縮到 40/36px（極矮橫向 38/34px），下限訂在 34px 以確保看得清楚。

## 環境變數

複製 `.env.example` 成 `.env` 給本機參考（`.env` 已被 `.gitignore` 排除）。
正式值請放在部署平台的環境變數，不要提交進 Git。

| 變數 | 用在哪 | 說明 |
| --- | --- | --- |
| `GAME_SERVER_URL` | 前端建置 | 前端要連的伺服器位址。留空＝用同源。只有前後端分開部署時才需要。 |
| `PORT` | 伺服器 | 監聽埠，預設 3030（Render 會自動注入）。 |
| `HOST` | 伺服器 | 監聽介面，預設 `0.0.0.0`。 |
| `GAME_ALLOWED_ORIGIN` | 伺服器 | 允許的前端來源，逗號分隔；`*` 表示不限制。正式環境請明確設定。 |
| `ROOM_TICK_MS` | 伺服器 | 對局推進間隔（毫秒），預設 500。 |
| `PING_INTERVAL_MS` | 伺服器 | 連線存活探測間隔（毫秒），預設 10000。 |
| `PING_TIMEOUT_MS` | 伺服器 | 探測多久沒回應就判定斷線（毫秒），預設 10000。 |
| `ROOM_IDLE_MS` | 伺服器 | 等待／結算畫面閒置多久自動收掉房間（毫秒），預設 30 分鐘；`0` 不收。 |

### server URL 是怎麼決定的

`public/js/config.js` 是全站**唯一**的連線設定入口，解析優先序：

1. 網址參數 `?server=https://example.com`（臨時覆蓋，方便測 staging 或跨電腦連線）
2. 建置時注入（`scripts/inject-server-url.js` 改寫 config.js 裡的一行）
3. 頁面本身就是伺服器送出來的（http/https 且不是 `file://`）→ 用同源
4. 都不是 → 只能玩單機

必須是 http/https 的絕對網址；https 頁面不接受 http 伺服器（瀏覽器會擋混合內容）。
格式不合會被擋下並記錄在 `Config.error`，**不會**靜默回退到 localhost 或任何寫死的網域。

```bash
# 本機測試
node scripts/inject-server-url.js --allow-local http://localhost:3030
# 正式部署
GAME_SERVER_URL=https://你的服務網址 node scripts/inject-server-url.js
# 還原成同源
node scripts/inject-server-url.js --clear
```

## 部署

Render 服務本身會提供完整遊戲（前端與線上伺服器）；也可以另用 GitHub Pages 放前端，連到同一台 Render 服務。

### 1. 後端：Render

1. 將專案推送到 [`PJH-Eric/draw-guess`](https://github.com/PJH-Eric/draw-guess) 的 `main`。
2. 在 Render 連接自己的 GitHub 帳號，選 **New → Blueprint**，連接該儲存庫並確認 `render.yaml` 中的 `draw-guess` Web Service。
3. 初次部署完成後開啟 Render 給的 HTTPS URL；`/health` 應回傳 `ok: true`。
4. 之後推送到 `main`，Render 會自動重新建置與部署。Render 的 build 階段會先跑 `npm test`。

- build：`npm ci --omit=dev && npm test`，start：`node server.js`，health check：`/health`
- `GAME_ALLOWED_ORIGIN` 預設允許 `https://pjh-eric.github.io`；服務也會自動允許 Render 提供的自身網址。改用自訂 Pages 網域時，請一併更新這個設定。
- 免費層限制：閒置約 15 分鐘會**休眠**，第一次連線要等十幾秒喚醒；
  檔案系統是暫時的；有連線、CPU 與頻寬配額；服務重啟房間就會消失。
  這個遊戲的房間本來就設計成「可拋棄的暫時狀態」，沒有任何長期資料要保存，所以不需要資料庫。

### 2. 前端：GitHub Pages

1. Settings → Pages → Source 選 **GitHub Actions**。
2. Settings → Secrets and variables → Actions → **Variables** → New repository variable
   - 名稱：`GAME_SERVER_URL`
   - 值：上一步拿到的 Render URL
3. 推上 `main` 就會自動建置並部署。

Pages 端**只需要這一個變數**，不需要（也不應該）放任何 Render 憑證或秘密。
沒設定的話站台仍會正常部署，只是線上對戰會顯示「連不到伺服器」，單機練習不受影響。

### 3. 分支與回滾

- `main` = production。先在 PR 或本機用同一份 commit 跑過 `npm run verify` 再合併。
- 回滾：`git revert <commit>` 後推上 `main`，Pages 與 Render 都會重新部署。
  Render 也可以在 Dashboard 直接 **Rollback** 到上一個 deploy。
- 查看記錄：GitHub → Actions 分頁；Render → 服務的 Logs 分頁。

### 首次上線仍需設定

Render 必須先在你的帳號中連接 GitHub 並建立 Blueprint。若同時使用 GitHub Pages，還須把 Pages Source 設為 **GitHub Actions**，並設定 `GAME_SERVER_URL` repository variable 為 Render 給的實際網址。
