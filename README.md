# 你畫我猜（draw-guess）

可愛風的畫圖猜謎小遊戲。輪流當畫家：畫家從三個題目挑一個畫出來，其他人把答案打進猜題框。
畫布是**小畫家風格**的（鉛筆、筆刷、直線、矩形、橢圓、橡皮擦、油漆桶、顏色、筆寬、復原／重做／全部清除）。

支援單機自己練習作畫與跨裝置線上對戰（大廳、房間、觀戰、邀請連結）。
手機、平板、桌機，直向橫向都可以玩。

---

## 快速開始

```bash
npm install
npm start
# 瀏覽器開 http://localhost:3030
```

Windows 可以直接雙擊 **`啟動遊戲.bat`**（會自動安裝相依套件、啟動伺服器並開啟瀏覽器）。

啟動後畫面會印出這台電腦的「同網段」網址，例如 `http://192.168.1.20:3030`。
同一個 Wi-Fi 的另一台手機或平板直接開那個網址，就能一起玩。

> 只想玩單機的話，其實連伺服器都不用開：把 `public/` 用任何靜態網頁伺服器送出去就可以。

## 怎麼玩

### 一局的節奏

| 階段 | 發生什麼事 | 時間 |
| --- | --- | --- |
| 選題 | 畫家從 3 個題目裡挑一個；沒選的話系統幫他挑第一個 | 15 秒 |
| 作畫 | 畫家作畫，其他人猜；全部猜中或時間到就結束 | 線上預設 90 秒（60–120 可調）；單機練習沒有電腦對手要等，直接給到上限 99999 秒 |
| 公布 | 公布答案與這一題的得分 | 7 秒 |

線上房間每個人輪流當畫家，每人畫 `rounds` 次（預設 2 次，最多 5 次）。全部畫完之後分數最高的人獲勝。
單機練習不計分也沒有這個「畫完就結束」的概念，直接給到上限 999 次，練夠了自己離開就好，不需要另外設定。

### 分數

- **猜對的人**：`100` + 時間獎勵（最多 `200`，剩越多時間越高）+ 名次獎勵（`60 / 40 / 25 / 15 / 10`）
- **畫家**：每有一個人猜中 `+40`；全部人都猜中再 `+60`。沒有人猜中就 `0` 分。

### 題目提示（畫家手上的三張牌）

提示不會隨時間自動出現，一律由**畫家主動按**，而且只能依序給、給了收不回來：

| 順序 | 提示 | 猜題者看到什麼 |
| --- | --- | --- |
| ① | 字數 | 題目有幾個字就出現幾條底線，例如「漢堡」→ `＿＿` |
| ② | 種類 | 公開題目的分類，例如「食物」 |
| ③ | 一個字 | 在底線上填回其中一個字，例如 `漢＿`。**最後一個字永遠不會翻開**，單字題沒有這一張 |

畫家還沒按提示前，猜題者連題目有幾個字都不知道。
提示區塊是畫家專屬的小面板，橫式擺在**畫布正上方、玩家名稱旁邊**，跟畫圖工具列分開；
一行放不下就自己掉到下一行（橫向時排到名稱左邊，避開右上角的固定按鈕）。
它刻意做小（高度 34～40px，低於一般按鈕的 46px 下限），把空間讓給畫布。

### 畫布工具（參考小畫家）

| 工具 | 快捷鍵 | 用法 |
| --- | --- | --- |
| 鉛筆 | `P` | 按住拖曳畫線 |
| 筆刷 | `B` | 同鉛筆，線粗一級 |
| 直線 | `L` | 從起點拖到終點，放開才定形 |
| 矩形 | `R` | 拖出對角線；可勾「填滿」 |
| 橢圓 | `O` | 拖出外框；可勾「填滿」 |
| 橡皮擦 | `E` | 擦掉畫錯的地方 |
| 油漆桶 | `F` | 點一下填滿封閉區域 |
| 復原 / 重做 | `Ctrl+Z` / `Ctrl+Y` | — |

**刻意沒有做的：作畫時的文字工具、對局中的聊天室。** 畫家如果在猜題進行中能打字，
就可以直接把答案寫出來或說出來，那就不叫你畫我猜了。對局中唯一能打字的地方是猜題框，
而且只有猜題者看得到它。左側操作摘要裡的「猜題紀錄」是唯讀的，顯示誰猜了什麼、誰猜對了。
等待畫面另外有個**聊天室**可以先聊幾句——那時候還沒有題目、也沒有答案，不會有外流的風險，
開始對局後就會跟著收起來，詳見下面「線上對戰」。

## 單機練習

單機練習**沒有電腦對手，也不計分**，就你自己一個人，單純練習下筆用的。

跟線上房間一樣走同一套 `Rules` 規則引擎，只是玩家名單裡永遠只有你一個人：
挑一個題目、盡情畫，畫完（或不想畫了）按**「跳過這題」**就換下一題並公布答案。
因為沒有電腦對手要等，**練習次數與每次可畫秒數不用設定，直接給到上限**（999 次、99999 秒）——
想練多久、練幾次都隨你，練夠了直接離開就結束（線上房間為了不讓其他真人乾等太久，上限小得多：5 次、120 秒，而且可以調）。

因為只有你自己，「猜題」「提示」「分數」這些跟別人比賽的東西在單機裡都用不到：
猜題框不會出現，「畫完了」這顆通知用的按鈕也沒有意義所以直接藏起來，只留「跳過這題」。

## 線上對戰

- **大廳**：開房、用房號加入、房間列表（房名、人數、等待中／進行中、觀戰人數、房主）、觀戰按鈕。
- **房間**：2–8 人**真人**（線上沒有電腦對手）；建立房間前會先在「開房間設定」選好房名、每人輪數、每題秒數與題目難度。進入等待中的房間後，房主仍可在中央「房間設定」調整規則——規則那三項改成下拉選單、標籤跟選單同一行（自己刻的按鈕＋清單，不是瀏覽器原生的 `<select>`，樣式跟卡片其他按鈕一致），房號跟玩家名單也一起縮小，這張卡才擠得出空間放下面的聊天室。寬螢幕（≥900px，例如平板橫向、桌機）這張卡改成**兩欄**：左邊房號、名單、規則，右邊邀請、聊天室，一個畫面看完不用捲；手機跟平板直向維持一欄。邀請區的網址欄跟「產生連結／複製／撤銷」排在同一行。**房主不用按「準備好了」**，只有一顆「開始！」——其他玩家都準備好就能開始；「改成觀戰」「離開房間」是小一號的次要鈕。卡片頂端會讓出右上角固定鈕的高度（手機上不會再蓋到標題），卡片開著時提示訊息改從上方出現，不會蓋住底部按鈕。玩家名單改成一列一個玩家、寬度滿版、文字置左（以前是置中的小 chip），不再另外顯示「x / y 位玩家」的字（列表本身數得出人數）；這幾項在手機直向跟平板都同步縮小過，不會有一邊擠一邊鬆的情況。
- **等待畫面的聊天室**：房間設定卡裡「邀請朋友」下面有個聊天室，只在還沒開始（`phase === 'waiting'`）跟結算畫面才會出現；一開始對局就整塊收起來，伺服器端 `room:chat` 也會直接擋掉，不是只有畫面上藏起來而已。別人聊天或按準備時，卡片是「就地更新」，打到一半的字、注音選字跟 iPhone 鍵盤都不會被打斷。
- **暱稱**：沒取名字的人不會全都叫「玩家」——第一次要用到名字時會自動配一個「形容詞＋小動物」的可愛暱稱（例如「勇敢小貓」），把欄位清空也會再配一個；同一間房裡撞名會自動接編號（小明、小明2），猜題紀錄才分得出誰是誰。
- **離開房間**：等待畫面的「房間設定」最下面有「離開房間」（房主是「退出房間」）；房主退出會把房主交給下一位**玩家**（沒有玩家才輪到觀戰者），最後一個真人退出房間就關閉。房主按「改成觀戰」時，房主也會交給下一位玩家；房間裡只剩自己一個玩家時不會出現「改成觀戰」（改下去房間就關了）。
- **一局結束後**：結算畫面上房主按「回房間」，大家回到等待畫面，可以聊天、改規則、重新按準備，再由房主開始。結算畫面也能聊天（答案都公布了）。以前是「全員投票再玩一局」直接開新局，改不了規則，有一個人掛機就全部卡住。
- **角色**：玩家（可畫可猜）與觀戰者（只能看）。位子滿了時，新來的人會被**明確**降為觀戰，不會默默佔位；
  對局進行中只要還有空位，中途加入或觀戰者按「下場一起玩」都能**直接當玩家**，自動排在目前順位的**最後一位**——
  這一輪還沒排到他就會排進去，不用等這一局結束。
- **邀請連結**：`?room=XXXX&invite=<token>`。token 32 個十六進位字元、有效期 60 分鐘、最多 20 人次，可撤銷。
  連結不綁身分——房主不用先幫對方選好「一定是玩家」或「一定是觀戰」，開啟後**會先停在大廳**顯示房號與可編輯的暱稱欄位，
  自己選要「加入當玩家」還是「加入觀戰」才送出加入請求；改暱稱不會改變自己選的身分。
- **斷線重連**：座位保留 60 秒，用同一個 `clientId` 回來就能回到原位。在房間或對局中**重新整理頁面會自動回到原本的房間**（房號只記在這個分頁，按「離開房間」就忘掉）；房間已經不在就停在大廳並說明原因。
  畫家斷線的話，題目列會顯示「畫家斷線了，最多等 15 秒」，15 秒沒回來就先跳過這一題（這一題不算他畫過，座位照樣保留）。
- **同一局裡離開又回來**：分數跟已經畫過的次數都會接回去，不會回來就歸零、又被多排一次畫。
- **身分憑證不外流**：用戶端存在本機的 `clientId` 是重新連線用的憑證，房間裡看到的是伺服器用 HMAC 算出來的公開 id，
  抄了別人的公開 id 也冒用不了他的座位（包括房主）。所有用戶端送來的欄位都只收真正的字串／數字，每個事件處理都有 try/catch，
  一個怪封包不會讓整台伺服器掛掉。

### 對局進行中中途加入

線上房間的對局中，人可以一直加入（只要位子沒滿），每個中途加入的人都會排在**目前順位的最後一位**；
如果一直有人加入，最後一位就會一直往後移，這一場的總題數也跟著重算，
不是開局時就訂死的一個數字（判定方式見下面）。

因為人數在結束前都可能再變，畫面上**一律只顯示目前第幾題**，不顯示「/ 總題數」的分母——
線上房間是因為人數變動導致總題數不是固定的；單機雖然沒有這個問題，但乾脆兩邊用同一套顯示方式，簡單清楚。

中途加入的人是**真正的玩家**，不是先當觀戰再手動下場：這一局結束、房主帶大家回房間之後，
他一樣坐在玩家席，不用額外操作；反過來，之前那種「先降觀戰、要自己點下場才能算數」的流程容易漏按。

結束的判定是**每個人都畫滿「每人畫幾次」**，不是「輪到第幾輪」：有人中途離開時，順位會往回退一格，
下一位不會被跳過，也不會有人連畫兩次或少畫一次；總題數 = 已經畫完的題數 + 每個人還欠的次數，一有人進出就重算。

### 房間什麼時候會關閉

房間生命週期只看**實體玩家**（坐在玩家席的真人）。觀戰者不算。

實體玩家歸零（最後一個真人離開、退出，或斷線超過 60 秒保留期）→ 伺服器**立刻**關閉房間：
邀請全部失效、對局計時器停掉、從大廳列表移除、廣播 `closed`，
觀戰者會看到「房間已結束」與回大廳的入口。關掉之後**不會**因為重新連線或舊邀請復活。

```
├── lib/rooms.js               房間狀態機（誰可以做什麼、邀請、生命週期）
├── public/
│   ├── index.html
│   ├── css/style.css
│   └── js/
│       ├── config.js          全站唯一的 server URL 設定入口
│       ├── rng.js             可注入的種子亂數
│       ├── words.js           題庫 + 形狀配方 + 形狀特徵比對
│       ├── rules.js           規則核心（狀態 + 行動 → 新狀態）
│       ├── ai.js              （目前沒有接進遊戲）會畫、會猜的電腦對手演算法，保留供未來需要時使用
│       ├── paint.js           小畫家風格的畫布引擎
│       ├── svgui.js           立體 SVG 按鈕、LOGO、頭像、工具圖示

│       ├── storage.js         本機偏好與戰績
│       ├── keyboard.js        手機軟體鍵盤修正
│       ├── online.js          Socket.IO 連線包裝
│       └── app.js             畫面、輸入與流程
├── scripts/
│   ├── inject-server-url.js   把 GAME_SERVER_URL 注入 config.js
│   ├── online-check.js        線上端對端（2 玩家 + 1 觀戰）
│   └── browser-check.js       無頭 Chrome 的 RWD／互動檢查
├── tests/verify.js            題庫、規則、AI、房間、設定解析的單元測試
├── .github/workflows/         CI 測試 + GitHub Pages 部署
├── render.yaml                Render 藍圖
└── 啟動遊戲.bat               Windows 一鍵啟動
```

### 設計原則

1. **規則核心與畫面／網路分離。** `rules.js` 只有「狀態 + 行動 → 新狀態」，時間由呼叫端傳進來。
   單機、伺服器、測試跑的是同一份，不會漂移。
2. **伺服器說了算。** 用戶端送的是「意圖」，房間權限由 `lib/rooms.js` 判斷、遊戲規則由 `rules.js` 判斷。
3. **隱藏資訊只走投影。** 答案只在 `state.wordId`；要送出去的東西一律經過 `Rules.toPublic(state, viewerId)`，
   只有當回合畫家拿得到答案與選字清單。操作摘要在揭曉前也不會寫出答案。
4. **可重現的隨機。** 題目、揭字順序、畫家順序都用可注入的種子亂數。

## 版面與設定

### 畫布最大化

畫布是正方形（筆畫座標統一在 0..1000，所以同一張圖在任何裝置上長得一樣），
邊長 = 可用空間的**較短邊**。所以「把高度讓出來」比什麼都有效：

- **直向**：操作列在畫布下方（寬度夠用、高度珍貴）。窄螢幕時工具、顏色、
  粗細三條各自變成可以橫向撥動的帶子，避免換行成四五排把畫布壓扁；
  「畫完了／跳過這題」釘在右邊不會被撥走（橫向時是上下疊在工具欄底部）。
  畫面比較高的手機（高度 ≥740px）上下本來就有空白，就改成顏色排兩排全部顯示、粗細與復原鍵不用滑，
  「跳過這題」自己一排撐滿；平板直向工具鈕放大到 48px 並撐滿整個寬度。

**「畫完了」不會結束這一題**：它只是廣播一句「某某說畫完了，快猜！」，時間照跑、畫家還能補筆畫。
這顆鈕**不會鎖起來**——補了幾筆想再叫大家看一次很正常，所以同一題想按幾次就按幾次，每按一次就再廣播一次。
真的要提早收掉這一題、公布答案的是下面那顆**「跳過這題」**
（對局設定裡的「跳過這一題（我畫不出來）」是同一個動作）。
- **橫向／寬螢幕（≥560px 且橫向）**：操作列移到畫布**右側**。
  橫向時寬度本來就有剩、高度才是瓶頸，這樣畫布可以吃滿整個高度。
  工具列固定分四組：畫圖工具 → 顏色 → 粗細 → 復原／重做／清除（三顆一定在同一排）。
  猜題者、觀戰者沒有工具列，右側這欄會收掉、畫布置中。題號只顯示在題目列（上排不再重複一個「第 N 題」）。

實測畫布邊長（畫家視角，工具列展開）：

| 尺寸 | 視窗 | 畫布 | 佔視窗較短邊 |
| --- | --- | --- | --- |
| 手機窄版直向 | 360×640 | 312×312 | 87% |
| 手機直向 | 390×844 | 370×370 | 95% |

### 工具按鈕的大小

畫布工具（工具、顏色、筆寬、填滿）**刻意做得比一般按鈕小**：它們數量多、
又要一直佔著畫面，做成 48px 會把畫布擠掉一大塊。實際尺寸是 44/40px，
窄版與矮橫向再縮到 40/36px（極矮橫向 38/34px），下限訂在 34px 以確保看得清楚。
畫家的三顆提示鈕同理（34～40px）。

這是有意識的取捨，不是疏漏 —— 自動化檢查對這幾顆按鈕另有 34px 的門檻，
其餘所有按鈕仍然強制 ≥46px。需要大命中區的人可以打開設定裡的
**「放大工具列」**，所有工具鈕會回到 ≥46px（檢查裡也驗了這一條）。

- **對局抬頭（題目與倒數）**：題目與剩餘秒數是隔著平板也要看得到的資訊，字級用 `clamp()`
  跟著螢幕流動放大（題目最大 2.6rem、倒數最大 1.8rem，倒數用 tabular-nums 不會跳動，
  剩 10 秒內會變紅並輕輕跳）。**橫向與寬螢幕時「上排狀態」與「題目提示列」合併成同一列**，
  省下的一整列高度全部還給畫布（實測畫布邊長：平板橫向 600→649、手機橫向 266→289、
  小手機橫向 251→274、桌機 732→777、平板直向 680→700、手機直向 364→372、
  手機窄版直向 297→317 —— 每一個尺寸都變大）。
- **畫布上方一列**：玩家名稱與分數，旁邊接著畫家的三張提示。
- **左側資訊欄**：操作摘要（目前階段、畫家、你的角色、你可以做什麼、題目提示、倒數、連線狀態、比分），
  下面接著「猜題紀錄」——系統事件與每一則猜題（含猜錯的）合成同一條時間軸，新的排在最上面。
  畫面上沒有另外的浮動紀錄面板，紀錄只有這一個地方。
  - 寬度 ≥ 1100px：常駐左欄，可以收起來讓遊戲主區變寬。
  - 窄版：從左側展開的浮層，不壓縮遊戲主區；用右上角的 📋 開關。
- **右上角設定**：所有畫面共用，按下開啟 Modal 彈窗（`role="dialog"`、`aria-modal="true"`、焦點鎖定、
  Escape 關閉、關閉後焦點回到原處）。包含背景音樂／音效的獨立開關與音量、下筆沙沙聲、猜題提示音、
  震動回饋、減少動態、放大工具列、暱稱與伺服器連線檢查、恢復預設。
- **開房間設定**（大廳按下「開一間房」後）：房名、每人輪數、每題秒數、題目難度。
- **等待中的中央「房間設定」**：房號（縮小顯示）、玩家名單（一列一個玩家、寬度滿版、置左）、房主規則（下拉選單、標籤跟選單同一行）、

## 環境變數

複製 `.env.example` 成 `.env` 給本機參考（`.env` 已被 `.gitignore` 排除）。
正式值請放在部署平台的環境變數，不要提交進 Git。

| 變數 | 用在哪 | 說明 |
| --- | --- | --- |
| `GAME_SERVER_URL` | 前端建置 | 前端要連的伺服器位址。留空＝用同源。只有前後端分開部署時才需要。 |
| `PORT` | 伺服器 | 監聽埠，預設 3030（Render 會自動注入）。 |
| `HOST` | 伺服器 | 監聽介面，預設 `0.0.0.0`。 |
| `GAME_ALLOWED_ORIGIN` | 伺服器 | 允許的前端來源，逗號分隔；`*` 表示不限制。正式環境請明確設定。 |
| `ROOM_TICK_MS` | 伺服器 | 對局推進間隔（毫秒），預設 500。 |

### server URL 是怎麼決定的

`public/js/config.js` 是全站**唯一**的連線設定入口，解析優先序：

1. 網址參數 `?server=https://example.com`（臨時覆蓋，方便測 staging 或跨電腦連線）
2. 建置時注入（`scripts/inject-server-url.js` 改寫 config.js 裡的一行）
3. 頁面本身就是伺服器送出來的（http/https 且不是 `file://`）→ 用同源
4. 都不是 → 只能玩單機

必須是 http/https 的絕對網址；https 頁面不接受 http 伺服器（瀏覽器會擋混合內容）。
格式不合會被擋下並記錄在 `Config.error`，**不會**靜默回退到 localhost 或任何寫死的網域。

```bash
# 本機測試
node scripts/inject-server-url.js --allow-local http://localhost:3030
# 正式部署
GAME_SERVER_URL=https://你的服務網址 node scripts/inject-server-url.js
# 還原成同源
node scripts/inject-server-url.js --clear
```

## 部署

Render 服務本身會提供完整遊戲（前端與線上伺服器）；也可以另用 GitHub Pages 放前端，連到同一台 Render 服務。

### 1. 後端：Render

1. 將專案推送到 [`PJH-Eric/draw-guess`](https://github.com/PJH-Eric/draw-guess) 的 `main`。
2. 在 Render 連接自己的 GitHub 帳號，選 **New → Blueprint**，連接該儲存庫並確認 `render.yaml` 中的 `draw-guess` Web Service。
3. 初次部署完成後開啟 Render 給的 HTTPS URL；`/health` 應回傳 `ok: true`。
4. 之後推送到 `main`，Render 會自動重新建置與部署。Render 的 build 階段會先跑 `npm test`。

- build：`npm ci --omit=dev && npm test`，start：`node server.js`，health check：`/health`
- `GAME_ALLOWED_ORIGIN` 預設允許 `https://pjh-eric.github.io`；服務也會自動允許 Render 提供的自身網址。改用自訂 Pages 網域時，請一併更新這個設定。
- 免費層限制：閒置約 15 分鐘會**休眠**，第一次連線要等十幾秒喚醒；
  檔案系統是暫時的；有連線、CPU 與頻寬配額；服務重啟房間就會消失。
  這個遊戲的房間本來就設計成「可拋棄的暫時狀態」，沒有任何長期資料要保存，所以不需要資料庫。

### 2. 前端：GitHub Pages

1. Settings → Pages → Source 選 **GitHub Actions**。
2. Settings → Secrets and variables → Actions → **Variables** → New repository variable
   - 名稱：`GAME_SERVER_URL`
   - 值：上一步拿到的 Render URL
3. 推上 `main` 就會自動建置並部署。

Pages 端**只需要這一個變數**，不需要（也不應該）放任何 Render 憑證或秘密。
沒設定的話站台仍會正常部署，只是線上對戰會顯示「連不到伺服器」，單機練習不受影響。

### 3. 分支與回滾

- `main` = production。先在 PR 或本機用同一份 commit 跑過 `npm run verify` 再合併。
- 回滾：`git revert <commit>` 後推上 `main`，Pages 與 Render 都會重新部署。
  Render 也可以在 Dashboard 直接 **Rollback** 到上一個 deploy。
- 查看記錄：GitHub → Actions 分頁；Render → 服務的 Logs 分頁。

### 首次上線仍需設定

Render 必須先在你的帳號中連接 GitHub 並建立 Blueprint。若同時使用 GitHub Pages，還須把 Pages Source 設為 **GitHub Actions**，並設定 `GAME_SERVER_URL` repository variable 為 Render 給的實際網址。
